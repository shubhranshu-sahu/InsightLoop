# InsightLoop Frontend — Comprehensive Documentation

This document serves as the single source of truth for the InsightLoop Frontend application, a core component of the B.Tech minor project. It is intended for developers, teammates, and college evaluators to understand the architecture, design systems, and JavaScript implementations that drive the user interface.

---

## SECTION 1: COMPONENT OVERVIEW

- **Component Name:** InsightLoop Frontend
- **Role in System:** The public-facing and dashboard UI of the platform.
- **Audience (Users):**
  1. **Business Owners:** Log in to view dashboards, create forms, track AI sentiment trends, and chat with their feedback data.
  2. **Customers (Public):** Scan a QR code to fill out the dynamic feedback form (no login required).
- **Deployment Platform:** Vercel (Free Tier).
- **Technology Choice:** Pure HTML5, CSS3, and Vanilla JavaScript.
  - **Why Vanilla JS?** This choice was deliberate to ensure fast development within the scope of a college project while ensuring all team members, regardless of their familiarity with complex frameworks like React or Angular, could understand and contribute to the codebase. It eliminates complex build steps (like Webpack/Vite) while maintaining performance.

---

## SECTION 2: TECHNOLOGY STACK

To maintain a pure vanilla ecosystem, external dependencies are loaded strictly via CDN (Content Delivery Network).

- **Bootstrap 5.3:** Used for the responsive grid layout, flexbox utilities, and structural alignment. (Components like modals use custom implementations to maintain the design aesthetic).
- **Bootstrap Icons 1.11 / Lucide Icons:** Used throughout the application for sleek, consistent SVG iconography.
- **Google Fonts (Inter & JetBrains Mono):** "Inter" is the primary sans-serif font for readability, while "JetBrains Mono" is used for code or specific numbers.
- **GSAP 3.12 + ScrollTrigger:** High-performance animation library used exclusively on the landing page for stagger animations and scroll-triggered fade-ins.
- **Chart.js 4.4:** Used on the dashboard and analysis pages to render complex data visualizations (Line, Doughnut, and Bar charts).
- **QRCode.js:** A lightweight library used on the client-side to generate and download QR codes dynamically based on a public form URL.
- **DOMPurify & Marked.js:** Used exclusively in the Chat interface to parse Markdown generated by the AI service into safe, sanitized HTML.

## SECTION 5: `config.js` — THE SHARED UTILITY MODULE

This file acts as the cornerstone of the frontend logic. It manages API URLs, Authentication state, and a central HTTP fetch wrapper. It is imported by almost every other `.js` file.

### 5.1 `API_BASE` Constant
- Points directly to the deployed Render backend: `https://insightloop-backend.onrender.com`.

### 5.2 Auth Object / Token Management
- `getToken()`: Retrieves the JWT string from `localStorage`.
- `saveAuth(token, business)`: Writes both the JWT and the JSON-stringified user details into `localStorage`.
- `getUser()`: Parses and returns the business object.
- `logout()`: Clears `localStorage` and `sessionStorage`, then forcefully redirects the user to `login.html`.
- `requireAuth()`: Automatically called at the top of every protected page (dashboard, forms, etc.). If no token is found, it intercepts execution and redirects to `login.html`.

### 5.3 `apiFetch(endpoint, options)` Wrapper
A robust centralized wrapper around the native `fetch()` API that ensures consistency across all backend calls:
- **Authorization:** Automatically injects `Authorization: Bearer <token>` into the headers.
- **Content-Type:** Automatically sets `application/json` for requests with a body.
- **Error Handling:** Parses non-200 responses and specifically looks for the `{ error: "message" }` format returned by FastAPI, throwing a JavaScript `Error` with that string.
- **401 Interception:** If a 401 Unauthorized status is encountered (and it's not during the login sequence), it triggers `logout()` automatically.

### 5.4 `showToast(message, type, duration)`
A lightweight UI notification system.
- Creates a fixed `div.toast-container` in the top-right corner if it doesn't exist.
- Injects a `div.toast.toast-[type]` containing the message.
- Applies CSS sliding animations and auto-dismisses after the specified duration (default 4 seconds).

### 5.5 `loadComponent(selector, url)`
Since this is pure HTML, we do not have React/Vue component loading. This function mimics it:
- Fetches a partial HTML file (like `sidebar.html` or `navbar.html`).
- Injects it into the target `selector` using `innerHTML`.
- **Crucial Fix:** Because browsers intentionally do not execute `<script>` tags injected via `innerHTML`, this function manually clones and re-appends any script tags found within the fetched component to ensure interactive elements (like the mobile hamburger menu) initialize correctly.

## SECTION 6: EVERY PAGE — COMPLETE DOCUMENTATION

### 6.1 `index.html` — Landing Page
- **Purpose:** Public marketing page explaining InsightLoop features.
- **Access:** Public.
- **Layout:** Sticky navbar, GSAP-animated Hero section, Scrolling Social Proof Ticker, 6-card Features Grid, 3-step "How It Works" list, and a Call-To-Action (CTA) footer.
- **JS Logic (`landing.js`):** Strictly used for initial load stagger animations and scroll-triggered revealing of elements using GSAP `ScrollTrigger`.
- **API Calls:** None. Fully static.

### 6.2 `feedback.html` — Customer Feedback Form
- **Purpose:** The actual form customers use to submit feedback.
- **Access:** Public. No login required.
- **URL Parameter:** Requires `?form_id=<uuid>` in the URL (which the QR code automatically encodes).
- **JS Logic (`feedback.js`):**
  - **Load Form:** `GET /api/feedback/form/:form_id`. Dynamically renders the title, description, and every question.
  - **Dynamic Inputs:**
    - `rating`: Renders 5 clickable SVG stars.
    - `text`: Renders a `<textarea>`.
    - `yesno`: Renders two toggleable buttons.
  - **State Tracking:** Tracks answered questions to update a visual progress bar.
  - **Submit:** Validates required fields, then calls `POST /api/responses/submit`. Replaces the form with an animated success checkmark upon a 200 OK.
  - **Error States:** Handles missing URL parameters, 404 Form Not Found, and 410 Inactive Form statuses with dedicated UI views.

### 6.3 `pages/login.html`
- **Purpose:** Business owner authentication.
- **Access:** Public. (Calls `redirectIfLoggedIn()` to push to dashboard if token exists).
- **Layout:** Split-screen (Branding left, Form right).
- **JS Logic (`auth.js`):** Reads email/password, posts to `POST /api/auth/login`. On success, calls `saveAuth` and redirects to `dashboard.html`. Show/hide password eye-icon toggle included.

### 6.4 `pages/register.html`
- **Purpose:** Account creation.
- **Access:** Public.
- **Layout:** Split-screen similar to login.
- **JS Logic (`auth.js`):** Validates password matching. Includes a password strength indicator (checking length, uppercase, numbers, symbols). Posts to `POST /api/auth/register`. On success, redirects to login with a success toast.

### 6.5 `pages/dashboard.html`
- **Purpose:** Main overview upon login.
- **Access:** Protected (`requireAuth()`).
- **Layout:** 6 Stat Cards, Sentiment Trend Line Chart, Urgency Doughnut Chart, Top Topics Bar Chart, Forms Table, Recent Responses Table, and an Alerts sidebar panel.
- **JS Logic (`dashboard.js`):**
  - Uses `Promise.allSettled` to execute 5 API calls concurrently, ensuring one failing endpoint (e.g., Alerts) does not crash the entire dashboard rendering.
  - **APIs:** 
    - `GET /api/analytics/dashboard` (Stat cards, Donut, Bar chart)
    - `GET /api/analytics/sentiment-trend?days=N` (Line chart)
    - `GET /api/analytics/forms-performance` (Forms Table)
    - `GET /api/analytics/recent-responses` (Recent Responses)
    - `GET /api/alerts` (Alerts Panel)
  - Interacts with Chart.js to initialize and update charts based on the selected date tab (7d/30d/90d).

### 6.6 `pages/forms.html`
- **Purpose:** Management of feedback forms.
- **Access:** Protected.
- **Layout:** Grid of form cards + "Create New Form" Modal + "QR Code" Modal.

  - Fetches `GET /api/forms` and maps them into `.il-card` HTML elements.

This modal renders the LLM-generated summary, topics, and sentiment at the top, followed by a dynamically generated list of exactly what the user answered for each form question (stars for rating, text for text).

## SECTION 7: THE SSE STREAMING IMPLEMENTATION (`chat.js`)

Because standard REST APIs wait for the entire response to generate before sending, they create a poor UX for LLMs (which take several seconds). Server-Sent Events (SSE) allows the AI to stream tokens one by one as they are generated.

### 7.1 Why `fetch()` instead of `EventSource`?
The native browser `EventSource` API handles SSE flawlessly, but **it only supports GET requests**. We need to send a `POST` request with a JSON body (thread_id, form_id, user_message) and an `Authorization: Bearer` header. Therefore, we utilize `fetch()` coupled with the `ReadableStream` API.

### 7.2 The Reading Loop
```javascript
const response = await fetch('/api/chat/message', { method: 'POST', ... });
const reader = response.body.getReader();
const decoder = new TextDecoder('utf-8');
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  // stream: true ensures multi-byte characters aren't split incorrectly
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  
  // The last line might be incomplete, keep it in the buffer
  buffer = lines.pop(); 
  
  for (const line of lines) {
    if (line.startsWith('data: ')) {
       const parsed = JSON.parse(line.replace('data: ', ''));
       // handle parsed.type ...
    }
  }
}
```

### 7.3 Event Handling Architecture
- **`{"type": "token", "token": " word"}`:** 
  The script concatenates the token to a `fullText` variable, parses it through `DOMPurify.sanitize(marked.parse(fullText))` (converting markdown `**bold**` to HTML `<b>bold</b>`), and injects it into the active bubble's `innerHTML`.
- **`{"type": "done", "sources": [...]}`:** 
  Fired at the very end. The loop breaks, and the `sources` array is passed to `appendSources()`, which generates the UI citation chips below the message.
- **`{"type": "error", "message": "..."}`:** 
  Injects red text into the bubble and gracefully terminates the stream loop.

## SECTION 8: RESPONSIVE DESIGN

The UI relies heavily on modern CSS layout primitives (Flexbox/Grid) and Bootstrap 5's responsive breakpoints.

- **Mobile Sidebar Drawer:** On screens `< 768px`, the `260px` fixed left sidebar disappears. A hamburger icon becomes visible in the top navbar. Clicking it slides the sidebar in from the left over a darkened `backdrop-filter: blur` overlay.
- **Form Card Grids:** `forms.html` uses Bootstrap classes: `col-lg-4 col-md-6 col-12`. Meaning: 3 cards per row on desktops, 2 on tablets, and stacked vertically on mobile.
- **Chat Layout:** On mobile, the two-panel Chat layout reflows vertically. The thread sidebar becomes a collapsible full-width selector at the top, allowing the main chat window to consume the entire screen height for an app-like experience.
- **Charts:** All Chart.js instances are initialized with `options: { responsive: true, maintainAspectRatio: false }` and wrapped in CSS containers with strict `min-height` rules to prevent them from squishing into unreadable slivers on small screens.

## SECTION 9: PROBLEMS FACED AND HOW THEY WERE SOLVED

### Problem 1: Page reload wiping authentication state
- **Issue:** A basic JavaScript variable `let token = ...` resets when the user hits refresh, logging them out instantly.
- **Solution:** Implemented `localStorage.setItem('insightloop_token', token)` upon login. The `requireAuth()` function reads from this persistent storage on every page load, ensuring sessions survive reloads.

### Problem 2: Dynamic component loading bypassing `<script>` execution
- **Issue:** The Sidebar and Navbar HTML partials contained inline `<script>` tags necessary for UI interactions (like the hamburger menu). Because they were loaded via `container.innerHTML = html`, the browser's security model refused to execute the scripts.
- **Solution:** Updated `config.js -> loadComponent()` to manually query all injected script tags, clone their attributes into a freshly created `document.createElement('script')`, and replace the dead tags with the live ones in the DOM.

### Problem 3: Chart.js rendering over old instances
- **Issue:** On the Analytics page, when a user selected a new form from the dropdown, the new Sentiment line chart would render *on top* of the old one. Hovering the mouse would cause the chart to visually glitch between the two datasets.
- **Solution:** Declared the chart instance variables (e.g., `let sentimentChart`) globally at the top of the JS file. Before creating a new chart, the code executes `if (sentimentChart) sentimentChart.destroy();` to wipe the canvas clean.

### Problem 4: SSE JSON stream fragmentation
- **Issue:** Occasionally, the browser's network layer would chop an SSE packet in half mid-transmission. E.g., chunk 1: `data: {"type": "to`, chunk 2: `ken", "token": "Hello"}\n\n`. Calling `JSON.parse` on chunk 1 crashed the script.
- **Solution:** Implemented a string `buffer`. The `TextDecoder({stream: true})` accumulates text, splits on newlines (`\n`), and specifically `pop()`s the final array item back into the buffer because a missing newline guarantees the packet is incomplete.

### Problem 5: QR Code image generation approach
- **Issue:** Initially, the backend generated a PNG file buffer. It was slow and cost server bandwidth.
- **Solution:** Switched to client-side generation using `QRCode.js`. The backend simply sends the URL string (`https://.../feedback.html?form_id=X`). The frontend library generates a local `<canvas>` element instantly.

## SECTION 10: WHAT WAS DROPPED OR SIMPLIFIED

Due to the strict deadlines of a B.Tech minor project evaluation, certain aspirational features were descoped:

1. **Reports Page:** The UI for generating downloadable PDF business intelligence reports was dropped. The `/summary` endpoint exists in the backend, but no frontend was built.
2. **GSAP Overuse:** Initial plans called for GSAP animations on every dashboard card load. This was dropped in favor of native CSS transitions (`transition: all 0.25s ease`) to ensure the dashboard felt instantaneous rather than "floaty". GSAP was restricted strictly to the landing page.
3. **Server-Side Pagination:** The `responses.html` page fetches all historical responses in one massive array and filters them via JavaScript on the client side. While inefficient for 100,000+ records, it is perfectly performant for the project scope and saved immense backend complexity.
4. **Phase 3 Charts in Chat:** The SSE reader loop explicitly has a scaffold for `if (parsed.type === 'chart') { appendChart(...) }`. The AI backend does not yet generate chart data, so this frontend code sits dormant.

## SECTION 11: DEPLOYMENT

- **Platform:** Vercel (Free Tier).
- **Architecture:** The Vercel deployment strictly serves static assets (`.html`, `.css`, `.js`, `.png`). It executes zero backend logic.
- **API Routing:** `js/config.js` hardcodes the `API_BASE` variable to point securely at the Render-hosted FastAPI/Node backend.
- **CORS:** During development (`localhost:5500` vs `localhost:5000`), Cross-Origin Resource Sharing errors were rampant. These were resolved purely on the Node/FastAPI backends by whitelisting `*` (or the Vercel URL in production). No frontend code changes were needed.
